# powerbi-sova

Retail & E-commerce BI Platform: Оптимізація продажів та асортименту ювелірної мережі

📌 Опис проєкту

Цей проєкт є симуляцією розгортання єдиної корпоративної платформи даних (DWH) та аналітичної BI-звітності для великої ритейл-мережі на прикладі специфіки ювелірного дому SOVA.
Мета проєкту — продемонструвати навички повного циклу роботи з даними (End-to-End): від алгоритмічної генерації сирих бізнес-даних та побудови реляційної архітектури сховища (SQL) до створення складних DAX-метрик та інтерактивних управлінських дашбордів (Power BI) за стандартами сучасної e-commerce та роздрібної аналітики.
Об'єм даних: 100,000 транзакцій (чеків) за період 2024–2026 рр.
Стек технологій: Python (Pandas, NumPy), SQL (SQLite / PostgreSQL), MS Power BI (Power Query, DAX).

🛠️ Покрокова реалізація проєкту

Етап 1: Алгоритмічна генерація датасету (Python)

Оскільки відкриті датасети (на кшталт Kaggle) не відображають специфіку українського ювелірного ритейлу, було написано кастомний Python-скрипт для генерації реалістичного масиву даних.
• Враховано сезонність: Штучно закладено комерційні піки продажів перед гендерними та календарними святами (Новий рік, 14 лютого, 8 березня), характерні для ювелірного бізнесу.
• Специфіка продукту: Сформовано залежність собівартості та роздрібної ціни від типу металу (Золото 585, 750, Срібло 925) та наявності дорогоцінного каміння (діаманти, смарагди).
• Канали продажів: Згенеровано дані для 30 офлайн-точок (ТЦ та стріт-ритейл у містах України) та окремого великого каналу E-commerce (Онлайн-магазин).

Етап 2: Проєктування Сховища Даних (DWH) та SQL-аналітика

Для забезпечення високої швидкості роботи BI-системи дані з плоских CSV-файлів було імпортовано у реляційну базу даних, спроєктовану за класичною архітектурою «Зірка» (Star Schema).

Схема даних містить:

• Fact_Sales — таблиця транзакцій (факти продажів, кількості, знижок та виручки).
• Dim_Products — довідник номенклатури прикрас (категорії, колекції, метали, вставки).
• Dim_Stores — довідник локацій мережі (міста, типи магазинів, менеджери).
• Dim_Customers — база даних програми лояльності (стать, вік, дата реєстрації).

Скрипт розгортання архітектури сховища (DDL):

sql
CREATE TABLE Dim_Products (
    ProductID INTEGER PRIMARY KEY,
    Category TEXT,
    Collection TEXT,
    Metal TEXT,
    Color TEXT,
    Gem TEXT,
    Cost REAL,
    Price REAL
);

CREATE TABLE Dim_Stores (
    StoreID INTEGER PRIMARY KEY,
    City TEXT,
    StoreType TEXT,
    Manager TEXT
);

CREATE TABLE Dim_Customers (
    CustomerID INTEGER PRIMARY KEY,
    Gender TEXT,
    AgeGroup TEXT,
    RegistrationDate TEXT
);

CREATE TABLE Fact_Sales (
    ReceiptID INTEGER,
    Date TEXT,
    ProductID INTEGER,
    StoreID INTEGER,
    CustomerID INTEGER,
    Quantity INTEGER,
    Discount REAL,
    Revenue REAL,
    Cost REAL,
    FOREIGN KEY (ProductID) REFERENCES Dim_Products(ProductID),
    FOREIGN KEY (StoreID) REFERENCES Dim_Stores(StoreID),
    FOREIGN KEY (CustomerID) REFERENCES Dim_Customers(CustomerID)
);


Валідація даних через SQL (Приклади аналітичних запитів):

Перед візуалізацією було проведено перевірку бізнес-логіки даних за допомогою аналітичних SQL-скриптів.
1. Аналіз ефективності ювелірних колекцій за маржинальністю:
sql
SELECT 
    p.Category AS [Категорія],
    p.Collection AS [Колекція],
    SUM(f.Quantity) AS [Продано шт],
    ROUND(SUM(f.Revenue), 2) AS [Виручка, грн],
    ROUND((SUM(f.Revenue) - SUM(f.Cost)) / SUM(f.Revenue) * 100, 2) AS [Маржинальність, %]
FROM Fact_Sales f
JOIN Dim_Products p ON f.ProductID = p.ProductID
GROUP BY p.Category, p.Collection
ORDER BY [Виручка, грн] DESC
LIMIT 5;


1. Порівняння каналів продажів та глибини чека (Офлайн роздріб vs E-commerce):
sql
SELECT 
    s.City AS [Місто],
    s.StoreType AS [Тип магазину],
    COUNT(DISTINCT f.ReceiptID) AS [Кількість чеків],
    ROUND(SUM(f.Revenue) / COUNT(DISTINCT f.ReceiptID), 2) AS [Середній чек (AOV), грн],
    ROUND(SUM(f.Revenue), 2) AS [Загальна виручка, грн]
FROM Fact_Sales f
JOIN Dim_Stores s ON f.StoreID = s.StoreID
GROUP BY s.City, s.StoreType
ORDER BY [Загальна виручка, грн] DESC;


Етап 3: ETL-процеси та розробка DAX-метрик у Power BI

Дані завантажено в Power BI Desktop. За допомогою Power Query проведено типізацію даних: текстові фінансові показники з американським роздільником (крапкою) успішно трансTransformation на грошові формати з урахуванням регіональної локалі, а пропуски в ідентифікаторах клієнтів опрацьовано як null (анонімні роздрібні гості).
Для глибокого аналізу було створено окрему таблицю динамічного Календаря (Time Intelligence) та розроблено систему DAX-метрик.

Основні DAX-формули проєкту:

• Комерційний оборот:
Загальна Виручка = SUM(Fact_Sales[Revenue])
• Ефективність маркетингу (Глибина середнього чека):
Середній Чек (AOV) = DIVIDE([Загальна Виручка], DISTINCTCOUNT(Fact_Sales[ReceiptID]), 0)
• Чиста операційна маржа (Грошовий вираз):
Чистий Прибуток (Маржа грн) = [Загальна Виручка] - SUM(Fact_Sales[Cost])
• Відсоток рентабельності продажів асортименту:
% Маржинальності = DIVIDE([Чистий Прибуток (Маржа грн)], [Загальна Виручка], 0)
• Порівняльний аналіз для CRM (Ефект клубу лояльності):
Середній чек (Лояльність) = CALCULATE([Середній Чек (AOV)], NOT(ISBLANK(Fact_Sales[CustomerID])))
Середній чек (Без картки) = CALCULATE([Середній Чек (AOV)], ISBLANK(Fact_Sales[CustomerID]))

📊 Структура та архітектура дашборду

Звіт спроєктовано у стриманому, преміальному стилі ювелірного бренду (фірмова палітра: графітовий, золотисто-бежевий акцент, платиновий фон) та розділено на 3 функціональні сторінки:
1. Огляд бізнесу (Executive Summary): Головні KPI для вищого керівництва (Виручка, Чеки, Маржа). Включає інтерактивний лінійний графік сезонності, що порівнює тренди 2024, 2025 та 2026 років, географічну карту продажів по містах України та розріз часток онлайн/офлайн каналів.
2. Аналітика асортименту (Product & Collection): Глибокий аналіз категорійної матриці. Матрична таблиця-дерево з інтегрованими золотистими індикаторами (Data Bars) відображає успішність капсульних колекцій. Сусідні деревоподібні діаграми аналізують дохід у розрізі дорогоцінних металів (проб) та вставок (діаманти, смарагди, сапфіри).
3. CRM & Лояльність (Customer Analytics): Аналітична панель для департаменту маркетингу. Демонструє чистий демографічний портрет покупця (вік/стать) із відсіканням невалідованих даних, порівнює поведінку лояльних та звичайних клієнтів (через метрики AOV) та трекає середню глибину наданих знижок за місяцями для оптимізації промо-кампаній.

📈 Бізнес-висновки на основі побудованої моделі:

• Сила бренду та CRM: Середній чек учасників клубу лояльності (77.20 тис. грн) майже вдвічі перевищує середній чек анонімних покупців (48.94 тис. грн), що підтверджує критичну важливість утримання клієнтської бази.
• Сезонна циклічність: Графіки чітко підтвердили закономірні для ювелірного ринку надвисокі стрибки виручки в грудні та лютому-березні, що дозволяє точніше прогнозувати закупівлі металу та планувати роботу логістики.
• Гнучкість ціноутворення: Середня глибина знижки коливається в межах 7.0% – 7.23%, що свідчить про контрольовану та стабільну маржинальну політику мережі без збиткових цінових демпінгів.
