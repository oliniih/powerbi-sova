# 💎 Retail & E-commerce BI Platform: Аналітика ювелірної мережі (SOVA )

## 📌 Опис проєкту
Цей пет-проєкт є моделлю розгортання **єдиної корпоративної платформи даних (DWH)** та системи управлінської BI-звітності для ювелірного ритейлу (на прикладі специфіки бренду **SOVA**).

Мета проєкту — продемонструвати володіння повним циклом роботи з даними (**End-to-End**): від генерації реалістичного датасету на Python та проєктування реляційної бази даних (SQL) до побудови моделі «Зірка», написання складних DAX-метрик та створення інтерактивних дашбордів у корпоративному стилі бренду (Power BI).

* **Масштаб даних:** 100 000 транзакцій (33 тис. унікальних чеків) за період 2024–2026 рр.
* **Технологічний стек:** Python (Pandas, NumPy, SQLite), SQL (DDL, DML, аналітичні запити), MS Power BI (Power Query, Data Modeling, DAX, Custom JSON Theme).

## 🛠️ Етапи технічної реалізації

### Етап 1: Алгоритмічна генерація датасету (`generate_data.py`)
Замість абстрактних відкритих датасетів створено кастомний Python-генератор під реалії українського ювелірного ринку:
* **Сезонність:** Закладено сплески продажів у пікові періоди (грудень, лютий, березень).
* **Ціноутворення:** Собівартість та роздрібна ціна динамічно формуються залежно від проби металу (Золото 585, 750, Срібло 925) та типу вставки (діаманти, смарагди, фіаніти).

### Етап 2: Архітектура Сховища Даних та SQL (`dwh_queries.sql`)
Дані структуровано у реляційній базі даних за схемою **«Зірка» (Star Schema)** з центральною таблицею фактів `Fact_Sales` та чотирма довідниками (`Dim_Products`, `Dim_Stores`, `Dim_Customers` та динамічний `Календар`).
* Проведено перевірку бізнес-метрик на рівні бази даних (розрахунок маржинальності колекцій, середнього чека по містах та ефективності програми лояльності).

### Етап 3: ETL (Power Query) та моделювання DAX
Дані завантажено в Power BI Desktop. За допомогою **Power Query** проведено очищення та типізацію даних: текстові фінансові показники з американським роздільником (крапкою) успішно трансформовано у грошові формати з урахуванням регіональної локалі, а пропуски в ідентифікаторах клієнтів опрацьовано як `null` (анонімні роздрібні гості).

#### Основні DAX-формули проєкту:
```dax
Загальна Виручка = SUM(Fact_Sales[Revenue])

Кількість Чеків = DISTINCTCOUNT(Fact_Sales[ReceiptID])

Середній Чек (AOV) = DIVIDE([Загальна Виручка], [Кількість Чеків], 0)

Чистий Прибуток (Маржа грн) = [Загальна Виручка] - SUM(Fact_Sales[Cost])

% Маржинальності = DIVIDE([Чистий Прибуток (Маржа грн)], [Загальна Виручка], 0)

Середній чек (Лояльність) = CALCULATE([Середній Чек (AOV)], NOT(ISBLANK(Fact_Sales[CustomerID])))

Середній чек (Без картки) = CALCULATE([Середній Чек (AOV)], ISBLANK(Fact_Sales[CustomerID]))

Середня Знижка % = AVERAGE(Fact_Sales[Discount])
```

## 📈 Ключові бізнес-інсайти проєкту
1. **Ефективність CRM:** Середній чек учасників програми лояльності стабільно перевищує середній чек анонімних покупців (близько **46–47 тис. грн** проти **39–40 тис. грн**), що підтверджує окупність маркетингових інвестицій у клієнтську базу.
2. **Драйвери прибутку:** Основний обсяг продажів формує **Золото 585 проби** (2,33 млрд грн), а найбільшу маржинальність у розрізі вставок генерують прикраси з **діамантами** (0,77 млрд грн чистого прибутку).
3. **Канали дистрибуції:** Роздрібні магазини у ТЦ приносять **61,2%** усієї виручки, стріт-ритейл — **35,75%**, а частка e-commerce складає **3,05%** із високим потенціалом до масштабування.
4. **Контроль знижок:** Середня глибина знижки по мережі тримається у вузькому контрольованому діапазоні (**6,97% – 7,23%**), що захищає операційну маржу компанії від розмивання під час святкових акцій.
